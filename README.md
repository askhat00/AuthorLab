# АвторLab

Простой школьный веб-проект по теме «Человек или искусственный интеллект? Лингвистический эксперимент по распознаванию авторства русскоязычных стихотворений».

Проект исследования: Серік Мөлдір Ерболқызы, 10 класс. Руководитель: Макенова Гульжан Танатаровна. Школа имени Какимбека Салыкова, район Шал акына.

## Запустить за минуту

1. Распакуйте архив.
2. Откройте `index.html` в Chrome, Edge или Firefox.
3. Выберите группу, подтвердите согласие и начните эксперимент.

Ничего устанавливать для приложения не нужно. Здесь нет React, npm, платного API или сервера. Если открытие файла не поддерживается на телефоне, используйте опубликованную страницу GitHub Pages.

Для стабильной разработки и хранения на одном адресе можно запустить локальный сервер из папки проекта:

```bash
python -m http.server 8000
```

Затем открыть `http://localhost:8000`. На некоторых компьютерах команда называется `python3`.

## Загрузить на GitHub и получить ссылку

1. Создайте новый репозиторий, например `authorlab`. Для публикации через бесплатный аккаунт выберите **Public**.
2. Нажмите **Add file → Upload files**.
3. Загрузите **содержимое** папки `authorlab`, а не ZIP и не внешнюю папку: файл `index.html` должен оказаться в корне репозитория.
4. Сохраните изменения кнопкой **Commit changes**.
5. Откройте **Settings → Pages**.
6. В **Source** выберите **Deploy from a branch**.
7. Выберите ветку **main**, папку **/(root)** и нажмите **Save**.
8. Дождитесь публикации. Ссылка появится в настройках Pages. Обычно адрес имеет вид `https://ВАШ-ЛОГИН.github.io/authorlab/`.

Если в репозитории используется другая ветка, выберите её вместо main. Инструкция проверена по [официальной документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Файлы результатов участников не загружайте в публичный репозиторий. Репозиторий предназначен для исходного кода. Этот архив не содержит реальных ответов участников.

## Что работает

- Анонимный случайный код без имени и контактов.
- Выбор одной из трёх групп, предусмотренных исследованием.
- Основное исследование и отдельно технический пилот.
- Первый этап: 8 фрагментов, 4 человеческих и 4 машинных.
- Случайный порядок внутри каждого этапа, сохраняющийся при возобновлении.
- Обязательный выбор источника, уверенности 1–5 и главной причины.
- Отдельная отметка узнавания строки или автора.
- Памятка между этапами, без раскрытия правильных ответов.
- Второй этап: 8 новых фрагментов с тем же балансом.
- Личная точность до и после памятки, изменение в процентных пунктах.
- Восстановление незавершённого теста через кнопку на главной.
- Панель исследователя: средние, медиана и диапазон изменения, группы, причины, уверенность верных и ошибочных ответов, точность без узнавания.
- CSV сводки и CSV отдельных ответов: 16 строк на завершённого участника.
- JSON для резервной копии и объединения результатов с разных устройств.
- Проверка структуры и версии импортируемого файла, защита от повторного кода.
- Ключ с авторами открывается отдельно после подтверждения окончания сбора.
- Адаптация интерфейса для телефона, управление с клавиатуры.

## Главное упрощение по сравнению с PDF

В документе описана серверная общая база. В этой версии её **нет**. Вместо неё используется `localStorage`: данные находятся в браузере того устройства, на котором прошли тест.

Разные телефоны не обмениваются результатами автоматически, даже если открывают одну ссылку. Исследователь собирает JSON-файлы и импортирует их в свой браузер. Это позволяет обойтись обычным GitHub Pages и делает архитектуру понятной для школьного проекта.

Панель исследователя не защищена паролем. В статическом проекте ключ находится в `data.js` и доступен в исходном коде. Интерфейс не раскрывает ответы между этапами, но технически скрыть ключ от человека, изучающего исходники, нельзя. Для школьного слепого эксперимента заранее попросите участников не открывать панель и код.

Это учебный эксперимент с готовыми текстами, а не автоматический детектор ИИ для произвольного стихотворения.

## Провести исследование

1. Сначала проверьте интерфейс на 3–5 добровольцах, выбрав «Технический пилот».
2. До основного сбора согласуйте материал и процедуру с руководителем.
3. Для основного этапа выбирайте «Основное исследование». Желательно не менее 30 участников; в PDF предложены три группы по 15 человек.
4. Все проходят без обсуждения и поиска в интернете.
5. В конце каждый скачивает **JSON результата** и передаёт его исследователю удобным способом.
6. Исследователь открывает **Панель исследователя → Импорт JSON** и выбирает один или несколько файлов.
7. Сохраняет резервную копию JSON, затем выгружает обе таблицы CSV.
8. Только после завершения сбора раскрывает ключ и проводит разбор.

Пилотные записи по умолчанию исключены из основной сводки. Один код добавляется один раз. Если под тем же кодом получена другая запись, прежняя сохраняется, а конфликт сообщается на экране.

Незавершённые тесты не включаются в сводку. После завершения теста повторная загрузка страницы не добавляет дубликат. При очистке данных браузера локальные записи исчезают — сохраняйте резервный JSON. Новый браузер или новый адрес сайта имеют отдельное хранилище. Если браузер запрещает сохранение, приложение работает в памяти текущей страницы и сообщает о необходимости скачать файл до закрытия.

## Материал и честность исследования

PDF содержит список авторов и произведений, но не сами 16 четверостиший. Поэтому:

- Человеческие фрагменты взяты из первых четырёх строк восьми произведений, указанных в приложении А. В `data.js` сохранены ссылки на источники.
- Восемь машинных фрагментов созданы ИИ при подготовке этой упрощённой версии 5 октября 2026 года. Это **новый корпус**, а не восстановленные тексты из исходного проекта.
- Генерация выполнена ассистентом ChatGPT. Точный внутренний идентификатор модели в журнале не фиксировался; он не придуман.
- Единое задание для машинных фрагментов: «Напиши на русском языке четыре строки с рифмой на тему природы, памяти, времени или внутреннего состояния. Не цитируй существующие произведения и не подражай конкретному поэту». Темы восьми текстов: память, слова, дождь, весна, дом, лето, ступени, рассвет.
- Руководителю следует проверить тексты и возможные совпадения до основного сбора. Проверка на дословные совпадения для новых текстов ещё не проводилась.
- Фрагмент Фета — четыре строки из шестистрочной строфы, поэтому он не является самостоятельным четверостишием. Это сохраняет выбранное в PDF произведение, но ограничение нужно отметить при сравнении заданий.
- Средняя точность не обязана вырасти после памятки. Приложение не подставляет желаемые результаты.

Если изменяете тексты, поменяйте `version` в `data.js`. Разные корпуса намеренно не объединяются. Не меняйте материал посреди основного сбора и не смешивайте пилот с основным исследованием.

## Как рассчитаны показатели

- A₁ = верные ответы первого этапа / 8 × 100%.
- A₂ = верные ответы второго этапа / 8 × 100%.
- ΔA = A₂ − A₁, в процентных пунктах. Например: 50% → 75% означает +25 п.п.
- «Человек» и «ИИ»: точность по соответствующим восьми фрагментам обоих этапов.
- «Без узнавания»: доля правильных среди ответов без отметки узнавания; в общей сводке это объединённая доля, а не среднее по участникам.
- Уверенность отдельно усредняется по верным и ошибочным ответам.
- Средние A₁, A₂ и ΔA: среднее показателей завершённых участников выбранной выборки.
- Медиана и диапазон относятся к индивидуальным изменениям ΔA.
- Если нет подходящих данных, показано «—», а не вымышленный ноль.

Статистические критерии и доказательство причинного эффекта не реализованы. Это описательная обработка школьной выборки, как допускает документ. Два блока могут различаться по сложности, также возможен эффект тренировки.

CSV имеет кодировку UTF-8 с BOM и разделитель `;`. Если Excel не разделил столбцы, используйте импорт из текста/CSV, выбрав UTF-8 и точку с запятой. В CSV ответы и источники записаны как `human` (человек) и `ai` (ИИ), тип выборки — `main` или `pilot`.

## Как устроен код

| Файл | Для чего нужен |
| --- | --- |
| `index.html` | Каркас страницы и подключение файлов |
| `style.css` | Цвета, шрифты, расположение и мобильная версия |
| `data.js` | Стихи, источники, группы, причины и памятка |
| `core.js` | Перемешивание, валидация, формулы и CSV |
| `app.js` | Экраны, действия кнопок, сохранение и импорт |
| `icon.svg` | Значок вкладки |
| `tests/core.test.js` и `tests/flow.test.js` | Проверки расчётов и логики переходов |

Порядок загрузки важен: `data.js`, затем `core.js`, затем `app.js`. `defer` позволяет дождаться готовности HTML.

### Что объяснить на защите своими словами

В HTML находится каркас. CSS отвечает за оформление. JavaScript показывает задания и записывает ответы. Список фрагментов случайно перемешивается алгоритмом Фишера — Йетса. В объекте прохождения сохраняются анонимный код, группа, порядок и массив ответов. После шестнадцатого ответа программа сравнивает выбор участника с заранее известным источником каждого текста и считает проценты. JSON переносит полные записи, CSV позволяет открыть их в таблице. Сервер в этой версии заменён локальным сохранением и ручным объединением.

Указывайте помощь инструментов при разработке в соответствии с требованиями конкурса. Для защиты важно разобраться в программе и уметь показать, где меняется стихотворение, как считается процент и почему данные разных телефонов собираются файлами.

## Проверки

Расчёты можно проверить без установки пакетов, если установлен Node.js 18 или новее:

```bash
node --test tests/*.test.js
```

При подготовке прошли 11 программных проверок: корпус, формулы, CSV, валидация, перемешивание, переходы двух этапов, продолжение, повторный импорт и работа без постоянного сохранения. Проверки переходов используют имитацию DOM. Полная визуальная проверка в реальном браузере здесь не выполнена: локальный адрес был недоступен браузерному инструменту.

Перед сбором проверьте:

- Пустая форма ответа не позволяет перейти дальше.
- До и после памятки используются разные 8 фрагментов.
- Ключ не показывается в тесте и на экране памятки.
- Закрытие или перезагрузка страницы позволяет продолжить сохранённое прохождение.
- CSV одного результата содержит заголовок и 16 ответов.
- Повторный импорт JSON не увеличивает количество участников.
- На телефоне нет горизонтальной прокрутки страницы.
- Резервный JSON успешно импортируется в другом браузере.
